# 错误检测优化与演示系统计划

## 目标

1. 错误输出格式统一为：`[错误类型] 行号: 错误描述`
2. Web端保留步骤信息、统计信息，确保错误信息清晰可读
3. 创建演示专用的错误样例手册（每个样例是完整可编译文件）

---

## 实施步骤

### 1. 统一语义错误输出格式

**修改文件**: [src/semantic/semantic_analyzer.c](src/semantic/semantic_analyzer.c)修改 `semantic_error()` 函数，统一输出格式为 `[语义错误-类型] 行 X: 描述`需要修改所有调用 `semantic_error()` 的地方，确保错误描述清晰：| 错误类型 | 输出格式示例 ||---------|-------------|| 变量未定义 | `[语义错误-变量未定义] 行 4: 变量 'c' 未声明` || 变量重定义 | `[语义错误-重定义] 行 6: 变量 'x' 重复定义` || 类型不匹配 | `[语义错误-类型不匹配] 行 7: 不能将 int* 赋给 int` || 数组下标错误 | `[语义错误-下标类型] 行 8: 数组下标必须是整数` || 非法解引用 | `[语义错误-解引用] 行 9: 不能对非指针类型解引用` || 函数参数不匹配 | `[语义错误-参数数量] 行 10: 函数 'add' 需要 2 个参数` || 返回类型错误 | `[语义错误-返回类型] 行 12: void 函数不应返回值` |

### 2. 统一语法错误输出格式

**修改文件**: [src/frontend/yacc.y](src/frontend/yacc.y)修改 `yyerror()` 函数：

```c
void yyerror(const char* s){
    printf("[语法错误] 行 %d: %s\n", yylineno, s);
}
```



### 3. 统一词法错误输出格式

**修改文件**: [src/frontend/lex.l](src/frontend/lex.l)修改未闭合注释的错误输出：

```c
printf("[词法错误-注释未闭合] 注释缺少结束符 */\n");
```



### 4. 创建演示专用错误样例手册

**新建文件**: [docs/error_demo_samples.md](docs/error_demo_samples.md)结构清晰的错误演示手册，每种错误提供：

- 错误类型名称
- 完整可编译代码（包含main函数）
- 预期错误输出

示例格式：

````markdown
## 1. 变量未声明

**错误类型**: 语义错误 - 变量未定义

**测试代码** (复制到 test_error.c):
```c
void main() {
    int a = 10;
    int b = c + 5;
    output_int(b);
}
````

**预期输出**:

```javascript
[语义错误-变量未定义] 行 3: 变量 'c' 未声明
```
